# 个人公开专利清单检索

用于回答“检索我发表/申请的专利”“某发明人有哪些中国专利”等问题。该流程与技术主题查新不同：目标是穷举公开记录并解决同名归属，不评价新颖性或创造性。

## 必要输入

- 发明人/设计人姓名；
- 至少一个已知申请人、任职单位或申请主体别名。缺少申请人时可以先返回候选集，但必须标注同名归属尚未核实；
- 用户明确提供的历史任职单位应作为多个 `--applicant` 参数保留，不把当前单位当作唯一过滤条件。

## 官方检索优先

优先使用国家知识产权局中国专利公布公告系统：

```bash
python3 tools/crawl/cnipa_epub_portfolio.py \
  --inventor "姓名" \
  --applicant "申请主体一" \
  --applicant "申请主体二" \
  --type all
```

脚本会：

1. 使用高级查询页 `#e72`“发明（设计）人”字段查询，禁止使用首页综合关键词框模拟发明人检索；
2. 对所选的发明公布、发明授权、实用新型、外观设计分别遍历全部结果页，并按申请号/公开号去重；
3. 解析申请号、公开号、申请人、发明人、名称及日期等页面可用字段；
4. 按一个或多个申请人过滤同名结果；
5. 在 `EPUB_PORTFOLIO_JSON` 中报告 `complete`、`stop_reason`、`pages_scanned`、候选公开记录数、去重后的匹配申请数和匹配公开记录数。

## 完整性门禁

- 只有 `complete: true` 时，才可把结果表述为“本次官方公开库完整检索结果”。
- 退出码 `3` 或 `complete: false` 表示分页未完整遍历；可以展示部分记录，但必须写明不完整及停止原因，禁止称为全部。
- WAF、加载超时、验证码、DOM 改版或依赖缺失属于检索失败，不等于零结果。验证码须交由用户处理，不破解。
- 任一公布公告类型的高级查询提交或分页重试耗尽时，整体必须为 `complete: false`；已成功类型的部分结果不能冒充全量。
- 无头模式反复出现 WAF/分页错误时，可用 `PLAYWRIGHT_HEADED=1` 重试一次；仍失败则停止高频请求并报告官方站点阻断，不循环轰击。
- `total_reported` 存在时，应与 `candidate_count` 复核；不一致时先诊断分页或解析遗漏。

## 同名归属

- `verified_inventor_metadata`：结果页明确列出目标发明人；
- `inventor_query_and_applicant`：列表页未显示发明人，但记录由姓名查询召回且申请人匹配；
- `inventor_query_only_unverified_namesake`：只有姓名查询依据，不能直接认定本人。

用户亲自确认某条归属时，可作为身份归属证据记录，但申请号、名称、申请人、公开号和日期仍以官方著录为准。不要仅凭技术领域相似度认定或排除。

## 输出要求

默认使用简体中文呈现结果；只有用户明确要求时才改用其他语言。脚本输出中的英文 JSON 字段名和内部状态码仅供程序判读，面向用户时应使用中文表头和中文说明，不直接展示为结论。其中身份依据按下列方式呈现：

- `verified_inventor_metadata` → “已由官方发明人著录核实”；
- `inventor_query_and_applicant` → “发明人查询与申请人共同匹配”；
- `inventor_query_only_unverified_namesake` → “仅姓名查询命中，同名归属待核实”。

至少列出：

- 申请号；
- 公开号/公告号（页面未提供时标注“待从详情页补录”，不得猜测）；
- 申请人；
- 专利名称；
- 申请日、公开/公告日（可获取时）；
- 身份匹配依据。

按申请号去重；授权公告与对应申请公开属于同一申请时，可并列展示法律事件，不重复计为两件申请。

## 范围说明

公布公告系统只覆盖已公开或已公告记录。尚未公开的内部提交、撤回且未公开的申请等不会出现在结果中，因此“公开记录数”不得写成“实际提交总数”。WebSearch、Google Patents 等只用于补充著录或交叉核验，不能用其较少的命中数覆盖官方完整结果。
